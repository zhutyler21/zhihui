# 知会原生应用

应用为独立 SwiftUI + AppKit macOS 程序，最低 macOS 14，Apple Silicon。源码在 `Sources/`，不包含 Google 图标、素材、代码或原应用动态库。自己的波形品牌标记与 Dock 图标在 `Design.swift` / `scripts/AppIcon.swift` 绘制。

## 构建和启动

在项目根运行 `./scripts/build-app.sh`，输出 `dist/知会.app`，使用本机 Xcode SDK 的 `swiftc` 编译及 ad-hoc 签名。可将应用复制到 `~/Applications`；应用内的 `ZhihuiProjectRoot` 是构建时的项目绝对路径，所以项目移动后应重新构建。源码、Python 环境和模型仍位于项目仓库。

双击应用时连接/自动启动项目 `.venv/bin/python3 -m backend.server`，只监听 `127.0.0.1:8768`。应用验证服务身份、版本、项目根和资料目录；如果此端口属于其他服务，会显示错误，并不关闭那个进程。退出只停止这个应用启动的子进程；复用已有正确服务时不取得进程所有权。

默认用户资料：`~/Library/Application Support/知会/`。本地鉴权令牌 `api-token` 为 0600，目录为 0700，后端日志 `backend.log`。测试可设置 `ZHIHUI_DATA_DIR`、`ZHIHUI_PORT`，或在隔离测试构建的 Info.plist 设 `ZhihuiDataDirectory` / `ZhihuiPort`（环境优先，正式构建无这些键）；接口自测只接受项目 `work/` 内目录及非默认端口。

## 页面

- 左侧导航会议、知识库、提问、回收站，底部明确显示本地模型状态。
- 会议页面采用导航、会议列表、白色圆角详情三个区域。名称就地修改，Return 保存；笔记自动保存，切换会议/页面和退出前再次保存。详情包含转写、笔记、中文纪要、附件四页。
- 会议可录音、导入音频、添加本场附件、问这场会议、导出 Markdown、移入回收站并恢复。单段转写的菜单支持校对或移入转写回收站；校对有保存/取消，时间与音频不改，纪要和检索由后端刷新。
- 知识库显示资料的读取/索引状态、会议关联、可预览文本和保存副本的位置，支持附件软删除与恢复。扫描 PDF 文字不可读时明确提示 OCR。
- 提问页的输入附近提供全部知识库、全部会议、指定会议三种范围。切换范围或会议清空对话，并取消正在生成的旧范围回答；返回旧任务不会污染新的对话。历史最多传 6 条消息。引用可点击查看实际证据并打开对应会议。
- 后台任务显示进度和中文阶段说明，可以取消；首次本地模型加载有说明。失败的音频块不会被丢弃，底部提供重试。

快捷键：⌘N 新建，⌘⇧R 开始录音，⌘⇧S 停止保存，⌘L 向当前会议提问，⌘Return 发送问题。文件选择和导出使用原生 `NSOpenPanel` / `NSSavePanel`。

## 录音与恢复

“麦克风”通过 `AVAudioEngine` 采集现场声音。第一次使用 `AVCaptureDevice.requestAccess(.audio)` 请求系统权限；拒绝时提示系统设置位置，不绕过权限。

“系统声音”使用 `ScreenCaptureKit`，由系统管理屏幕与系统音频录制权限。没有注册屏幕图像输出，没有保存图像，只捕获播放音频并排除当前应用自身声音。

第三种“麦克风 + 系统”同时采集两路，适合戴耳机的在线会议。先请求两种权限，再开始声音采集；各路独立重采样到 16kHz 单声道，使用 `AVAudioTime.hostTime` / `CMSampleBuffer` 主机时间对齐，各衰减 6 dB 后相加成同一时间线。保留 2 秒回调等待，按实际采样时间而非回调到达顺序混音；安静超过 0.5 秒的流排空转换器尾部，下一次声音重新建立转换器。极晚的音频前缀另存带原始偏移的补充 WAV，不丢弃；其尚未发布的余量继续混音。没有音频重复提交，麦克风与系统在同一时间的实际同时说话会保留叠加声音。

建议双路模式戴耳机，避免扬声器把对方声音再次传入麦克风。应用排除自身播放声音，但没有声学回声消除，不能声称扬声器环境下完全没有回录。

音频在串行队列经 `AVAudioConverter` 转为 16kHz 单声道，按 10 秒 PCM16 WAV 原子写入 `recordings/<session UUID>/`，每个文件为 0600。麦克风独立模式以帧计数计算连续 `start_seconds`；系统独立模式和双路模式都用主机时间定位，静音期间没有系统回调时补零，停止按实际墙钟补足尾段，不把 15 秒断流压缩掉。不使用后台推理耗时推算时间。停止会排空转换器，并保存不足 10 秒的最后一块。

新录音和导入音频使用同一个实际队列维护器 `AudioQueueState`：起点取会议已存结尾、待转写正时长结尾、已知真实结尾的最大值。未知时长导入文件顺序处理，完成第一份后才推进下一份位置，不影响其他会议。录音停止的尾块按真实时长累加，已知结尾随队列持久化；因此仅首个10秒已转写、另20秒仍待处理时，再导入会从30秒后开始。

外部音频选择完成后先异步复制到 `recordings/imports/<UUID>/`，目录0700、文件0600，再加入持久队列；复制期间显示“正在保存音频”。随后移动用户原文件不影响转写。复制目标会议在选择时确定，不随界面切换改变；复制期间不能删除那个会议、退出会等待复制结束。保留自己的音频副本，本版不自动清理，也不会删除用户原音频。

应用用 `pending-transcriptions.json` 记录待处理块和已知结尾（兼容旧版数组格式），逐一向后端 `/transcribe` 提交并轮询。每块带稳定 `request_id`，配合后端持久幂等防止退出后重送产生重复文字。转换后的 WAV 保留，本版不提供永久清理音频的界面。应用退出会先停止采集、保存尾块和队列，再结束自己的后端；下一次启动重试未完成任务。退出后的普通问答/纪要任务不自动重发。

提问的停止按钮在 HTTP POST 尚未返回任务编号时也立即失效化当前会话；迟到的任务编号会发送取消请求，不显示旧范围答案。会议选择、详情刷新和转写回收站有同样的最新请求校验；异步改名完成不会覆盖已经切到另一场会议的名称。

切换会议从第一次异步请求前锁定旧详情的编辑、导入和开始录音控件，并显示“正在打开会议”。笔记编辑绑定也检查这个锁，不接受加载期间对旧笔记的修改；先保存旧稿，再读取新会议及回收站。只有最新选择能解锁和显示结果，保存失败则保留旧笔记、取消切换并恢复编辑。正在运行的录音仍可通过侧边栏停止。

同一会议的后台详情刷新也有笔记修订保护：编辑与确认保存会递增修订；请求前捕获修订、草稿和未保存状态，全部读取返回后才决定是否采用服务器笔记。如果期间已有新编辑、保存或更新的刷新，保留当前草稿和已确认保存的笔记/纪要，仅刷新其他字段。笔记确认修改后旧纪要失效，避免旧读取响应把旧稿或旧纪要带回来。

权限请求窗口出现时需要用户手动授权；麦克风/系统声音硬件路径仍需在本机真正录音验证。转换器自测不等于硬件权限与实际声音采集测试。

## 已执行的原生测试

1. `dist/知会.app/Contents/MacOS/知会 --self-test`：真实 `AVAudioConverter` 路径以 48kHz 双声道 23.75 秒合成音频输入，输出 16kHz 单声道两块 10 秒和一个 3.75 秒尾块；验证 WAV 头、样本总数、连续偏移、文件权限。双路测试额外输入 23.75 秒麦克风流及从 2.5 秒开始的 4.25 秒系统流，验证输出总时长仍为 23.75 秒、重叠区幅值为两路之和、之前/之后/尾段幅值一致；并验证迟到 3200 帧的 1000 帧已发布区域补充保存、2200 帧进入待发布区域。首轮测试发现静音流转换尾部迟迟未排空，加入 idle 排空后通过。回执 `work/native-audio-tests/receipt.json`。它没有请求麦克风权限，不能证明硬件录音成功。
2. `ZHIHUI_DATA_DIR="$PWD/work/native-client-test" ZHIHUI_PORT=8872 dist/知会.app/Contents/MacOS/知会 --api-self-test`：启动真实 Python 后端，使用应用真实 HTTP 客户端验证会议新建、中文改名、导出、软删除/恢复、600令牌、无效令牌拒绝、复用服务退出不杀、自己的子进程停止。回执 `work/native-client-test/native-client-receipt.json`。它不构成界面渲染或模型效果验证。
3. `./scripts/test-native-state.sh`：构建独立无GUI测试程序，不启动同一个应用 bundle。实际调用产品的队列维护、复制、会话和音频转换器，验证三块录音仅第一块完成后导入从30秒开始、多个未知时长文件依次推进、不同会议隔离、真实停止尾块、JSON保存/重建已知时间、复制后移动原文件仍可读。真实 URLSession 客户端连接隔离的延迟HTTP服务，验证创建任务前停止、迟到任务取消、新会话不受旧响应影响。系统单路音频测试输入0–5秒有声、5–20秒无回调、20–25秒有声，输出保留25秒及真实20秒恢复位置；双路测试继续单独覆盖。每次回执写在新的 `work/native-regressions/<timestamp>-<pid>/`，保留早期证据，不把合成PCM当作硬件权限测试。
