# 知会：独立中文本地会议应用

目标：构建 macOS 中文本地会议应用，支持本地音频转写、中文摘要、文件知识库语义问答、全部会议及指定会议检索。源码、模型、开发环境和证据集中在本项目。用户数据在应用自己的 Application Support 目录。历史记录迁移不修改来源数据库。

## 必须证明的功能

1. 可启动的原生中文 .app；会议可新建、改名、查看、导入音频、录音、编辑笔记、导出和移入回收站/恢复。
2. 本机 SenseVoice 转写真实中文音频。
3. 本机开源语言模型生成中文摘要和回答，不用外部 AI 服务。
4. 本机 embedding 语义检索：来源包含转写、笔记、摘要和文件。问答可选全部知识库、全部会议、指定会议，答案附来源，指定会议不混入其他会议。
5. 文件导入/去重、会议关联、读取状态、资料预览。TXT/MD/CSV/JSON/HTML/文字 PDF/DOCX/PPTX/XLSX；无文字 PDF 显示需 OCR 的状态。
6. 历史记录和旧自定义会议附件只读导入，稳定标识防重复。原记录不改动。
7. 真实运行、持久化读取、无外部 AI 网络请求、隔离和失败路径测试；原生 UI 实际验证。权限需要用户手动授予时明确记录。
8. 界面重视美观与易用。实际窗口验收留白、层次、阅读宽度、中文文案、导航与主动作、窄窗口、loading/error/empty 状态和引用展开，不能仅凭编译成功声称美观完成。

## 协作边界

主线程负责模型/依赖配置、backend/engines.py、本地推理和全量验收。
后端实现线程负责 backend/store.py、backend/server.py、backend/documents.py、后端测试及对应文档，不修改 engines.py。
原生界面实现线程负责 Sources/、scripts/build-app.sh、原生录音和对应说明，不修改后端代码。
每个线程读取本文件，独立检查自己的输出，避免覆盖其他线程文件。

## 固定接口 v1

后端：Python ThreadingHTTPServer，仅 127.0.0.1，端口由 --port 指定（默认 8768），--data-dir 指定数据目录，--token-file 读取或创建 0600 随机令牌。所有请求使用 Authorization: Bearer <token>。GET /api/health 也鉴权。
JSON 所有字段 snake_case。错误 HTTP 非 2xx：{"error":"可读中文说明"}。成功列表用 {"items": [...]}。

- GET /api/health -> {"ok":true,"models":LocalModels.status(),"data_dir":str}
- GET /api/meetings?trash=0|1 -> items of {id,title,title_automatic,created_at,updated_at,deleted_at,segment_count,attachment_count,summary}
- POST /api/meetings {title?} -> 同一 meeting 字段。id UUID。默认标题 会议 YYYY-MM-DD HH:mm。
- GET /api/meetings/{id} -> meeting 字段加 {note,segments:[{id,text,start_seconds,end_seconds,created_at,deleted_at}],attachments:[source字段]}，segments 只含未删除。
- PATCH /api/meetings/{id} {title?,note?} -> meeting。验证 1–100 字标题；保存 title 后 title_automatic=false，后续纪要保留此名称。
- POST /api/meetings/{id}/trash -> {ok:true}; POST /api/meetings/{id}/restore -> {ok:true}。不提供永久删除。
- POST /api/meetings/{id}/segments {text,start_seconds?,end_seconds?} -> segment（用于导入人工文本及真实音频结果，主接口不伪造转写）。
- POST /api/meetings/{id}/segments/{segment_id}/trash -> {ok:true}; POST .../restore -> {ok:true}。摘要和索引失效。
- GET /api/meetings/{id}/segments?trash=1 -> items。
- POST /api/meetings/{id}/transcribe {path,start_seconds?:0} -> {job_id}；读取指定本地音频并复制录音副本，LocalModels.transcribe，保存 segment 并 embed。导入/录音同一接口。依序提交录音块，偏移秒数确保顺序。
- POST /api/meetings/{id}/summarize -> {job_id}；模型以中文生成总览、决定、行动项（负责人/期限）、未决问题；标明资料未提及，不编造。title_automatic=true 时在纪要核对后生成主题名称，与纪要一并提交；job result 追加 title_changed 与 title_warning，命名失败保留旧名称而不丢弃有效纪要。
- POST /api/sources {paths:[绝对本地路径],meeting_id?:null} -> {job_id}；复制不可变文件副本、抽取文本/分块/embed。相同会议+hash 去重。单个失败返回读取状态，不回滚已完成的独立文件。
- GET /api/sources?meeting_id=... -> items of {id,meeting_id,filename,path,text,extraction_note,status,created_at,chunk_count}；不传范围查询所有。status indexed|unreadable|error|indexing。
- GET /api/sources/{id} -> source 字段。
- POST /api/sources/{id}/trash -> {ok:true}; POST .../restore -> {ok:true}。
- POST /api/ask {question,scope:"all"|"meetings"|"meeting",meeting_id?:null,history?:[{role,content}]} -> {job_id}；question 1–2000 字。scope=meeting 必须有效未删除会议；在检索前 SQL 严格过滤范围。job result {answer,citations:[{label,meeting_id,meeting_title,source_id,filename,text,score}],scope,meeting_id}。上下文为证据、不是指令。history 最多近 6 条；范围切换界面清空历史。没有证据直接明确说明，不能使用其他范围历史补充事实。引用标签统一 [1] [2]。
- GET /api/jobs/{job_id} -> {id,state:"queued"|"running"|"done"|"error"|"cancelled",progress:0..1,message,partial,result,error}。
- POST /api/jobs/{job_id}/cancel -> {ok:true}，生成/录音必须检查 cancel_event。
- POST /api/import-foresight {path?:原 database.sqlite 绝对路径,attachments_path?:旧 meeting-files.sqlite} -> {job_id}；read-only SQLite 快照，导入到新数据库、按 event_id+timestamp 防重复；post_event_summarization、手写笔记、完整 transcript、关联来源/旧自定义附件；不导入邮件/通讯录。处理真实字段以本机 schema 为证据。
- GET /api/meetings/{id}/export -> {filename,markdown}，可在原生界面另存。
- GET /api/search?q=... -> items meeting（名称/笔记/转写文字搜，非问答语义检索）。

## 模型接口（主线程）

backend/engines.py 提供 LocalModels(root: Path)，status() -> dict，transcribe(path: str, cancel_event=None) -> {text,duration_seconds,language}，embed(texts: list[str]) -> list[list[float]]，generate(prompt: str, system: str, on_chunk=None, cancel_event=None, max_tokens=1600) -> str。
模型离线从 root/models/ 加载，不主动下载；并发使用锁，lazy load，生成中可取消。缺失模型/不支持文件要中文错误。generation 函数 on_chunk 接收新增文本。

## 原生界面约定

SwiftUI + AppKit，bundle id io.local.zhihui.meetings。左侧会议、知识库、提问、回收站；主区域会议名称、笔记、转写、摘要、附件。录音时明确状态；默认麦克风，可选系统声音（ScreenCaptureKit），停止后保存并索引。模型状态和首轮等待可见，文件选择用原生 NSOpenPanel，导出 NSSavePanel。向本次会议提问自动选 scope=meeting；提问页面范围选择就在输入附近。
应用启动 Python 后端（项目 .venv/bin/python3 -m backend.server），项目根通过 bundle Info.plist ZhihuiProjectRoot 固定配置。运行现有健康服务先验证 token/version，退出只终止自己启动的 child PID，避免影响其他应用。标准日志写本项目 work/ 或应用数据目录，不写用户文件夹根目录。

## 验收约束

测试全部写入本项目 work/ 下隔离数据目录。不得向用户真实 Foresight SQLite 写入测试数据，不得把自动化成功当作真实 UI 成功。任何未经实际验证的项目保持未完成。
