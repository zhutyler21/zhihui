# 会议资料与实时会场的职责分离

版本：0.7.1 / build 19，2026-10-16。本次修改界面组织、导航和文案，不更换模型、后端接口或日常资料格式。0.7.0 的模型与投屏能力保留其原验收范围。

## 最终行为

| 位置 | 主要任务 | 直接可见操作 |
| --- | --- | --- |
| 会议资料，默认打开 | 查看、编辑和整理本场资料 | 转写、笔记、中文纪要、附件；右上角只有一个“进入实时会场”入口，副标题说明“录音 · 翻译 · 大屏” |
| 实时会场，同一主窗口中的独立页面 | 控制当前现场会议 | 录音、声音来源、实时翻译开关、语言设置、大屏入口；下方只预览最新一段原文，不混入笔记等内容标签 |
| 实时翻译大屏，独立窗口 | 给参会者展示多语字幕 | 按本场会议显示原文及所选译文，可移到外接屏全屏；主窗口可同时返回资料页查看笔记 |

“返回会议资料”恢复进入前的内容标签。进入会场前调用原有笔记保存逻辑；保存失败时留在资料页并显示错误，切换期间锁定本页防止重复操作。异步保存完成后还会核对发起时的会议 ID；切换会议会清除当前会场页面状态。返回资料不停止录音或关闭独立大屏。

资料页的“问这场会议”收进会议更多操作；导出、音频导入与可恢复删除继续使用原流程。转写区的已保存译文仍属于可回看的会议资料。

会场中，“实时翻译”使用原生开关，直接开启或关闭；“语言设置…”和“打开翻译大屏”保持稳定名称，讲话与译文语言独立显示。录音时语言开关/设置沿用原有锁定规则，大屏入口可继续使用。旧聚合布局候选的日志保留在任务 work 中，其窗口证明不冒充最终分离布局的验收；该候选没有安装到日常 App。

## 设计依据与技能

用户反馈明确要求资料阅读和现场控制各有职责，最终不再把两类任务合并成一个大卡片。

参考 Apple 当前 [Layout](https://developer.apple.com/design/human-interface-guidelines/layout)、[Toolbars](https://developer.apple.com/design/human-interface-guidelines/toolbars)、[Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons)：相关任务应分组、主次应清楚、控件应与内容区分，布局变化后仍应可辨认。具体采用“默认资料页 → 实时会场 → 独立字幕窗口”的结构，是本项目对这些原则的应用，不代表 Apple 的官方产品背书。

- SwiftUI Expert：使用原生 Button、Toggle、Picker 和 ViewThatFits，保持 macOS 14 支持；按会议 ID 保护导航和大屏范围；笔记先保存再离开。
- ui-ux-pro-max：用于任务分组、稳定标签、字体和对比；沿用 Design.swift，正文 16、辅助文字 13，检查浅色、深色和较小窗口。
- Context7：先解析 SwiftUI 官方文档库，再查 ViewThatFits 与 switch Toggle 的当前用法；来源和结果保存于 `work/translation-entry-20261016/ctx7-library.txt`、`swiftui-docs.txt`。本轮无需重新研究参考网站实现，未重复调用 REA。

主要源文件：`Sources/Views.swift`（资料页及保存后导航）、`Sources/MeetingLiveView.swift`（会场页）、`Sources/TranslationViews.swift`（快捷开关与设置）、`Sources/ProjectionView.swift`（统一设置名称）。版本与安装工具同步为 0.7.1 / 19；中英文 README 同步操作路径。
