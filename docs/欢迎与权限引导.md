# 知会欢迎与权限引导

当前已安装：0.4.0 / build 14。设置页增加三个必要模型的下载、真实字节进度、暂停与继续，以及逐项绿色勾选。仅安装一次，正式版显示声音权限 0/2、模型 3/3；系统提示由用户处理，本轮未操作权限按钮、系统设置或重测录音。完整范围见[欢迎页验收记录](欢迎页验收记录.md)。

## 使用流程

首次启动先显示知会主题欢迎页，点击“开始设置”准备声音与本地模型。两项声音权限和三个必要模型均完成后，“进入知会”才可用。点击进入时重新校验全部模型文件并读取系统状态，保存引导完成记录后进入会议主界面。

模型卡按中文转写、会议与资料检索、中文纪要与问答显示 SenseVoice、BGE、Qwen3。启动时离线校验现有文件，不自动下载。缺失时点击“下载所需模型”，显示收到的字节和总大小，可暂停；已收到的内容保留，点击“继续下载”重试。固定文件清单为 `Resources/ModelCatalog.json`，全部 23 个文件约 2.61 GB；文件验证通过后才显示已准备。网络下载失败不会解除进入门禁。

- **麦克风**：读取 `AVCaptureDevice.authorizationStatus(for: .audio)`；首次请求使用系统弹窗，拒绝后可打开系统设置。
- **系统声音**：当前录音器使用屏幕与系统声音的合并权限，检查 `CGPreflightScreenCaptureAccess()`；请求由 `CGRequestScreenCaptureAccess()` 发起。macOS 将它列在“录屏与系统录音”中。录音器只接收音频，不注册或保存屏幕图像输出。
- 每一项的勾选是系统状态标识，没有手动勾选替代授权的入口。系统弹窗返回、从设置回到应用、点击“重新检查”和点击进入都会读取状态。系统要求重新打开应用时，按提示退出并重新打开。
- 无文件选择、辅助功能或整盘读取权限的预先请求。添加资料时继续使用现有原生文件选择器。

完成记录保存在实际资料目录的 `onboarding.json`（文件 0600），日常目录与验收目录各自保存。回访启动时仍先检查权限与模型：记录已完成但任一权限或模型缺失，会回到设置页；未知版本或损坏记录会重新显示欢迎页。只有主界面分支创建 `RootView` 并启动本机服务，会议菜单和快捷操作在引导中禁用。

已经进入主界面的当次会话，不会因返回应用而突然销毁笔记编辑区或录音界面；录音器在每次开始录音时仍检查对应权限。下次完整启动重新检查权限与模型。退出时保留部分下载，下载子进程先正常停止，必要时只结束本应用拥有的该子进程。

## 验证范围

`bash scripts/test-onboarding.sh` 使用独立目录执行实际流程状态代码，覆盖八种启动组合、旧记录不能绕过缺权限、进入时检查过期勾选、请求结束不等于授权、连续点击互斥、保存失败与重试、完成不能返回欢迎、私有文件保存及损坏记录。权限服务以受控替身隔离系统弹窗；测试不修改真实授权状态，不把它作为真实 TCC 弹窗证明。

build 14 增加模型缺失、默认提供者拒绝进入、模型状态过期及完成记录门禁测试。`bash scripts/test-model-preparation.sh` 测真实子进程字节事件、拆分 JSON、重复下载互斥、异常/非零退出、暂停/退出清理、模型文件移走与现有模型离线校验。Python 下载器测试使用真实小文件 HTTP，覆盖断点续传、错误响应、校验失败和互斥。原生下载界面通过相同下载器下载独立合成小文件；这不代表重新下载数 GB 公网权重或重新测试真实授权。

Metal 欢迎效果由 `scripts/build-app.sh` 编译到发布包 `Contents/Resources/default.metallib`，最低 macOS 14。开发环境需要 Apple Metal Toolchain；本次已通过 Apple 的 `xcodebuild -downloadComponent MetalToolchain` 安装。

build 7 已实机检查欢迎页浅深色、真实折射、上下/侧向拖动与回弹、暂停/继续和权限流程；build 9 验证主窗口同进程重开，build 9/10 再次走过欢迎、真实 2/2 勾选与进入主界面。用户完成 build 11 的系统关联后，日常主界面、笔记预览和资料保留已确认。用户要求不再操作权限设置；本轮 build 12 仅验证指定 UI 增量，完成后安装一次，新系统提示由用户处理，没有重新测试正式引导或录音。帧率、完整动作视频和减少动态效果的系统设置切换尚未实测；不以编译或数值探针替代这些证明。

引导期间还修复两项启动/退出边界：尚未连接服务的全新模型退出时，不再用空快照覆盖已有待转写队列；退出使未完成的后台启动失效，避免等待中的网络检查结束后又启动子进程。两个问题均在独立目录先复现失败，再用实际 AppModel / BackendHost 复验通过；不以这些无窗口检查替代真实应用退出验收。
