# 会议纪要与自动名称 · 2026-10-16

生成中文纪要与“停止并整理”共用纪要流程。未手动命名的会议在纪要核对后，由本机 Qwen 模型概括议题，生成简短中文名称，与纪要在同一事务中保存；会议列表和页内标题随后刷新。重新整理自动名称会随内容更新，手动保存名称会关闭本场自动命名。命名失败仍保存有效纪要，保留旧名，并在完成提示中说明。

## 实现边界

- `backend/meeting_titles.py` 定义本地命名提示与严格 JSON / 长度 / 常见数字检查。命名输入是已核对纪要；数字支持只读取原始资料正文，排除来源编号和文件名。数字检查不等于完整语义事实验证；人名、公司、繁简体及议题质量仍依赖模型和内容核对。
- `meetings.title_automatic` 新增字段默认保护名称；新建时没有指定名称则设为自动。显式创建名称、导入名称或 PATCH 保存名称均保留手动归属。
- 历史迁移仅将本应用创建时间对应的精确默认日期名称标为自动，其他名称保留。历史没有手动归属记录，无法区分用户过去恰好手动保存了同样的默认日期名称；迁移不改变原来的名称、笔记、纪要或关联。
- 提交前重新检查会议存活、内容版本与取消状态。标题实际变化也递增版本，使旧问答引用不能继续使用旧名称。保存期间的手动改名 / 资料编辑使旧任务拒绝提交；手动同名保存也建立保护。
- SwiftUI Expert 的状态流指导用于 AppModel 的完成通知；沿用现有会议选择和刷新保护，保留未提交的标题草稿。没有新增界面按钮或模型下载。
