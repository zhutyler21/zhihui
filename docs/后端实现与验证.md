# 后端实现与验证

此文档只说明后端的证明范围；原生界面、真实音频识别准确度和真实千问生成质量由整体验收另行验证。

后端是自主编写的 Python 标准库 HTTP 服务，仅监听 `127.0.0.1`。所有接口，包括健康检查，都要求 `Authorization: Bearer`。令牌文件和数据库权限为 `0600`，数据目录为 `0700`。来源副本与原音频保存在应用自己的数据目录；原始文件不修改。

## 运行

在项目根目录执行：

```sh
.venv/bin/python -m backend.server --port 8768 --data-dir "$HOME/Library/Application Support/知会" --token-file "$HOME/Library/Application Support/知会/api-token"
```

开发验收改用项目 `work/fixture/` 下的隔离目录。SIGTERM/SIGINT 关闭自己的监听端口并请求停止后台任务，不终止其他应用。

## 资料与范围

`backend/store.py` 保存会议、片段、来源、向量、任务状态。转写、笔记、摘要和文件统一分块建立索引，embedding 默认每块最多 420 字、重叠 60 字。向量使用 SQLite JSON 存储，余弦排序；向量来自主线程实现的真实本地 BGE 模型。

检索首先在 SQL 内筛选全部知识库、全部会议或指定会议。会议软删除、片段软删除和附件软删除都会排除；指定会议必须存在且未删除。片段校对和删除清除旧摘要与向量；校对保留原时间范围和原音频副本。索引更新用 revision 检查，旧任务不能提交覆盖新正文的向量。

问答只提供当前范围的证据，并统一生成 `[1]` 等引用。历史最多接收近 6 条，旧助手事实不会进入模型证据；空范围直接返回没有资料，不调用生成模型。事实缺失要求明确写“资料未提及”。这是证据边界和提示设计，不能替代对真实模型输出的验收。

检索的同一条 SQL 同时取得文字、source revision、父会议 content_version 和片段标识。生成完成时再次确认每个引用来源、父会议、片段仍可见且版本相同；这一步与最终任务发布共用 Store 锁。生成中编辑、删除或先删后恢复资料都会拒绝旧答案，任务显示“资料已变化，请重新提问”，错误/取消同时清除临时生成文本。内部版本字段不会进入 API 引用。

摘要处理全部资料：每次最多 9000 字原文，长会议先逐组提取决定和行动项，再按需分层合并，最后生成总览、决定、行动项和未决问题。会议资料生成过程中变更时拒绝保存过期摘要。没有使用抽样来绕过长会议。

## 文件与导入

`backend/documents.py` 支持 TXT/MD/CSV/JSON/LOG/HTML、文字 PDF、DOCX、PPTX、XLSX。使用本地 pypdf/python-docx/openpyxl 或 ZIP/XML 读取，不调用网络。无文字 PDF 显示需要 OCR；不支持的类型保留副本并显示未读取。单个文件上限 256 MB、读取文字上限 50 万字、PDF 上限 500 页。Office 解压总内容上限 80 MB、单项上限 20 MB。文字超出上限明确标记已截取；知识库只索引实际读取的部分。

文件复制到私有临时副本、流式计算 hash 后原子发布，相同会议和内容 hash 去重。独立文件失败显示 `error`，已经完成的其他文件不会回滚。复制后的全部抽取/会议可见性检查/INSERT 路径由 finally 管理，只清理本次新建且尚未被持久来源引用的副本；提交前取消、会议中途移入回收站不会留下孤儿附件，原文件不动。后台任务可取消，完整转写先持久保存；embedding 失败保留正文并标记索引失败，后续启动会重试未完成索引。

取消发生在完整转写、摘要或文件已经提交之后，最终任务返回 `done`、真实保存结果和 `warnings`，提示“资料已保存；取消请求到达时提交已完成”。提交前取消则为 `cancelled`，清空草稿。静音音频返回 `done`、空 text、真实 duration、`segment:null`、`indexed:false`，保留录音副本，不创建空片段也不阻塞录音队列。

Foresight 导入使用 SQLite `mode=ro` 和 `query_only=ON` 读取并 `backup` 到 `work/fixture` 私有快照，不写原数据库。稳定标识为 `event_id + timestamp`，完整会议正文用单次新库事务发布。读取真实 `event_transcript_table` 的完整片段/turns、`post_event_summarization`、`notes_table` 手写内容。原关联资料只接受显式会议关联、`source_type=2` 且能够验证的本地文档路径。这是本机版本观测到的文档分类，**不是通用 source_type 枚举**：本机 type2 含 `.xlsx`/`.md` 文档；type5 为 asset/log 来源，type7 为网络图片，type6 为已单独导入的生成纪要。其余类型即使指向本地 TXT 也跳过并报告，不导入全局邮件/通讯录。旧自定义附件按明确的 `event_id + event_timestamp` 关联导入和去重。

## 与固定接口一致的扩展

- `GET /api/health` 另含 `app: "zhihui"`、`version: 1`、`project_root`，用于原生端确认现有服务身份。
- 全部 `created_at` / `updated_at` / `deleted_at` 使用 Unix 秒。
- `POST transcribe` 可附 `request_id`。相同会议、请求和音频 hash 返回同任务；同请求音频变更报错。任务结果含 `duration_seconds`、`segment` 和索引状态。中断后重试如果正文已经保存，不重复转写或创建片段。
- `GET /api/sources?trash=1` 可与 `meeting_id` 组合，支持附件恢复界面。
- `PATCH /api/meetings/{id}/segments/{segment_id} {text}` 支持人工校对真实转写；回收站片段需先恢复。
